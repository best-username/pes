# winner-mods: модифікації скриптів-переможців

Agent Skill для Claude Code. Бере скрипт реклами-переможця і за кілька хвилин дає моушн-дизайнеру пачку
модифікацій: нові хуки, перші фрази й текст на екрані. Кожна модифікація змінює **рівно один** елемент
переможця, тож тест покаже, чи саме цей елемент рухає клік. Результат: бриф для дизайнера (CSV і Markdown)
з готовими назвами реклам для трекінгу.

Кейс: SockLock (ДЗ 3, MarTech). Зараз команда робить 240 модифікацій на місяць, по ~3 години дизайнера
кожна. Щоб подвоїти spend до $800k, треба ~500. За словами дизайнера, до половини дня в нього йде на
переписування хуків і текстів під переможця. Цю частину бере на себе скіл; монтаж лишається за дизайнером.

## Як працює

1. Користувач вставляє скрипт-переможця (або називає ID з `references/winners.md`).
2. Claude ділить його на 5 елементів (`hook`, `first_line`, `on_screen`, `body`, `cta`), читає контекст
   продукту й приклади модифікацій, що вже вигравали, і пише варіанти: ~40% хуки, 30% перші фрази,
   30% текст на екрані, кожен з іншим важелем (число, питання, впізнавана сцена, контраст, слова аудиторії).
3. `scripts/mods.py` детерміновано перевіряє кожен варіант і повертає JSON із проблемами:
   - змінено рівно один елемент, і лише хук / першу фразу / текст на екрані;
   - хук ≤ 10 слів, рядок тексту на екрані ≤ 40 символів;
   - немає заборонених тверджень (`references/banned-claims.txt`: гарантії, медичні обіцянки, фейковий дефіцит);
   - немає майже-дублікатів у пачці та в історії модифікацій цього переможця;
   - є одне речення-обґрунтування (гіпотеза для тесту).
4. Claude виправляє лише ті варіанти, що не пройшли (до 3 раундів), решту відкидає з причиною.
5. Експорт: `briefs/<ID>-brief.csv` і `.md`, ID `W012-M001…` і назви реклам `SL_US_W012-M001_hook_ai` (мітка `_ai` відрізняє модифікації зі скіла від ручних);
   модифікації додаються в `mods-history.csv`, тож наступна пачка не повторить уже зроблене.

Модель пише, скрипт перевіряє: креатив від LLM, правила — в коді, який не помиляється і не «забуває»
інструкцію.

## Встановлення

Потрібні Claude Code і `python3` 3.9+ (лише стандартна бібліотека). Ключів API, мережі й залежностей немає.

```bash
git clone https://github.com/best-username/pes && cp -r pes/winner-mods ~/.claude/skills/
# або лише для одного проєкту:
mkdir -p .claude/skills && cp -r pes/winner-mods .claude/skills/
```

У claude.ai: Settings → Capabilities → Skills → завантажити zip з папкою `winner-mods`.

## Запуск

У Claude Code в будь-якій робочій папці:

```
Ось наш переможець W012, зроби 10 модифікацій:
<вставити текст скрипта>
```

Скіл також підхоплюється на «нові хуки для переможця», «варіації скрипта» тощо. Бриф і історія
пишуться в поточну папку.

Скрипт можна запустити й без Claude, на готовому JSON:

```bash
python3 winner-mods/scripts/mods.py winner-mods/examples/W012-variants.json --check-only
python3 winner-mods/scripts/mods.py winner-mods/examples/W012-bad-variants.json --check-only   # 5 проблем у 6 варіантах
python3 winner-mods/scripts/mods.py <variants.json> --history mods-history.csv --out-dir briefs
```

Коди виходу: `0` — ок, `1` — є проблеми (нічого не записано), `2` — помилка вводу.

## Демо

У `examples/` — повний прогін на вигаданому переможці W012 «Sock graveyard»:

| Файл | Що це |
|---|---|
| `W012-winner.txt` | Вхід: скрипт-переможець |
| `W012-variants.json` | 10 варіантів, які написав Claude; перевірку пройшли |
| `W012-bad-variants.json`, `W012-bad-check.json` | Навмисно погані варіанти й що на них сказав скрипт |
| `briefs/W012-brief.md`, `.csv` | Вихід: бриф для дизайнера |
| `mods-history.csv` | Історія після експорту (M001–M010) |

Дані в `references/winners.md` і `examples/` вигадані для демо. Для реальної роботи заміни
`winners.md` на поточних переможців з рекламного кабінету й модифікації, що їх побили.

## Вартість

Оцінка (не вимірювали): одна пачка ≈ 10k токенів на вхід і 3k на вихід. У Claude Code це входить у підписку команди.
Через API: ≈ $0,05 на пачку на Sonnet 5.5 ($2 / $10 за 1M токенів), ≈ $0,10 на Opus 5.5 ($4 / $20);
60 пачок на місяць ≈ $3–6.

## Метрики успіху

Пілот: 2 тижні, 2–3 дизайнери, поруч із ручним процесом.

| Метрика | Зараз | Ціль пілоту | Як міряти |
|---|---|---|---|
| Adoption: частка модифікацій, зроблених через скіл | 0% | ≥ 60% у пілотних дизайнерів | Реклами з `_ai` у назві (звіт Meta) / усі модифікації пілотних дизайнерів (їхні задачі в трекері) |
| Час на модифікацію | ~3 год | ≤ 1,8 год | Самозвіт дизайнерів / таймтрекер |
| Модифікацій на дизайнера на тиждень | ~10 | ~16 | Задачі дизайнерів у трекері |
| CPC модифікацій зі скіла проти ручних | — | не гірший за ручні | Звіт Meta: реклами з `_ai` у назві проти решти модифікацій |
| Win rate (частка модифікацій, що б'ють переможця) | — | не нижчий за ручний | Те саме |
| Частка варіантів, що пройшли перевірку з першого разу | — | ≥ 70% | Вивід `--check-only` |

**Критерій зупинки (домовитись до старту):** adoption < 50% через 2 тижні або CPC модифікацій зі скіла
гірший за ручні на > 10% — зупиняємо й розбираємо причину, а не допилюємо наосліп.

## Наступна ітерація

1. **Готові відео замість брифу.** Дизайнер один раз експортує переможця без тексту на екрані;
   `whisper-cli` дає таймкоди фраз, а `ffmpeg` вшиває текст кожного варіанта в потрібні секунди і
   рендерить MP4 з назвою реклами. Варіанти тексту на екрані виходять готовими до запуску, варіанти
   хука — чернеткою з титром (новий голос потребує якісного TTS). Монтаж такої модифікації — хвилини
   замість годин.
2. **Петля результатів:** імпорт CSV-звіту Meta за назвами реклам → скрипт сам оновлює `winners.md`
   модифікаціями, що виграли. Приклади, а не правила, вчать модель найкраще.
3. **Локалізація DE/FR:** той самий формат, нова довідка ринку й перевірка довжини під мову.
4. **Експорт у трекер:** рядки брифу одразу в Airtable / таску дизайнера.

Далі `winner-mods` стає першим скілом маркетингового плагіна для всієї команди: наступні — локалізація
переможців під DE/FR на тому ж ядрі (приклади, перевірка правил, назви реклам) для Head of Marketing,
потім аналізатор воронки квізу для Growth PM. Порядок — за EGP і за тим, наскільки ефект залежить лише
від інструмента.
